F1  One malformed event crashes the consumer, and it then stays stuck on every restart. Events it has
    already read are lost. (Violates the A-stop rule in DECISIONS: "no event that it read is lost".)
    Reproduced with a fake SSE server (scripts/probe_consumer.py, scripts/probe_poison.py):
      - a data line with invalid UTF-8      -> UnicodeDecodeError (iter_sse .decode, not caught)
      - meta.id is a list or object         -> TypeError: unhashable (`event_id in self.seen`)
      - type is a list                      -> TypeError: unhashable (`row["type"] in EDIT_TYPES`)
      - timestamp/length/namespace > int64  -> dlt PipelineStepFailed "Integer exceeds 64-bit" in _flush
      - a bad HTTP status line              -> http.client.BadStatusLine from _connect (only OSError is
                                               caught around _connect; HTTPException is caught only in the read loop)
    In every case the pending micro-batch (up to 2,000 events or 5 s) is dropped. Since the checkpoint is
    older than the bad event, a restart sends the same Last-Event-ID, the replay sends the same event
    again, and the consumer crashes again. probe_poison.py: 3 restarts, stream_raw stays [e1, e2], and
    e4 and e5 never land. `make stream` stops before dbt runs.
    Suggested fix, ready to apply:
      a) pipeline/stream_consumer.py iter_sse: `raw.decode("utf-8", errors="replace")` (or catch
         UnicodeDecodeError per line and drop that event).
      b) Make _field_problem reject wrong types before flatten:
           INT64_MIN, INT64_MAX = -2**63, 2**63 - 1
           def _is_int_or_none(v):
               return v is None or (isinstance(v, int) and not isinstance(v, bool) and INT64_MIN <= v <= INT64_MAX)
           # in _field_problem, after the meta/length object checks:
           if meta is not None and not isinstance(meta.get("id"), (str, type(None))): return "meta.id is not a string"
           for key in ("type", "wiki", "server_name"):
               if not isinstance(event.get(key), (str, type(None))): return f"{key} is not a string"
           if not _is_int_or_none(event.get("namespace")): return "namespace is not an integer"
           if not isinstance(event.get("bot"), (bool, type(None))): return "bot is not a boolean"
      c) _read_until: `except (OSError, http.client.HTTPException): return` around self._connect().
      d) run(): wrap the loop in try/finally so self._flush() runs on the way out (or at least log loudly).
      Add tests for each case in tests/test_stream_consumer.py::test_consumer_wrongTypedFields_* style.

F2  check 7 (test_late_events_count) never runs. It is not selected by `make stream` or by the
    "quality gate" in DECISIONS. The test reads read_parquet('out/marts/late_events/*.parquet') and has no
    ref(), so dbt does not tie it to late_events. `--select +late_events` leaves it out.
    Verified: compared `dbt ls` for both make selections with the list of all tests. The only tests not
    selected are test_late_events_count and the two dim_date tests (see F10). Run on its own it PASSES
    (60 late = 60).
    Fix: add `-- depends_on: {{ ref('late_events') }}` as the first line of
    transform/tests/test_late_events_count.sql. That keeps the N-3 direct read of out/marts/.

F3  `make stream` fails unless `make build` has already run. fact_edit reads lake/sitematrix_sites, which
    only batch_load writes. Verified: with sitematrix_sites missing, `IO Error: No files found that match
    the pattern "lake/sitematrix_sites/*.parquet"`, and all 14 downstream nodes are skipped. .gitignore says
    the grader removes lake/ and out/ first, so running `make stream` before `make build` fails.
    Fix (Makefile, stream target, first line):
        test -d lake/sitematrix_sites || uv run python -m pipeline.batch_load
    Or document the order in DECISIONS "Make targets".

F4  A null namespace or wiki duplicates rows in the incremental window_5min, double-counts edits and fails
    the build. The unique key is [window_start, wiki, namespace, actor_type]. delete+insert cannot match
    NULL key parts, so the old row stays and the recomputed row is added.
    Reproduced (scripts/probe_nullns.py): edits with no "namespace" key in two loads that hit the same
    window. After run 2, window_5min holds both (…, None, 'human', 2) and (…, None, 'human', 3), and
    unique_combination_of_columns fails.
    How NULLs get in: _field_problem allows a missing namespace or wiki. A wrong-typed namespace or wiki
    (string or object) also ends up null (F5).
    Fix: reject the event in the consumer (F1b), or in window_5min filter
    `and f.namespace is not null and f.wiki is not null` (or coalesce to a sentinel such as -1 / '').

F5  Wrong-typed fields drift the lake schema without any warning. namespace="talk" lands as a new dlt
    variant column namespace__v_text with namespace=NULL. wiki={"x":1} lands as wiki__x with wiki=NULL.
    The models read read_parquet(glob) without union_by_name, so DuckDB keeps the first file's schema and
    drops the variant column (verified with a 3-file drift test). The edit then has a null namespace or
    wiki (see F4) and no error is raised. The fix is the same validation as F1b.

F6  bot handling is inconsistent. flatten() sets `bot = bool(event.get("bot"))` but
    `actor_type = "bot" if event.get("bot") is True`. With bot="false" (a string) the lake row has
    bot=True and actor_type='human' (verified in the landed parquet). test_stream_totals_per_wiki groups
    the oracle by `bot`, the mart groups by actor_type, so check 5 would fail. Fix: one rule, e.g.
    `"bot": event.get("bot") is True`, plus the F1b bool check.

F7  Amendment A says the population year is recorded, but the published mart does not record it.
    population_year exists only in dim_place (in the warehouse). out/marts/mart_monthly_obligations has
    no year column, and its column `county_population_2024` holds the 2021 estimate for 09001, 09003,
    09005, 09009, 09011 and 09013 (13 mart rows). DECISIONS says analysts read out/marts/ only.
    Fix: add `p.population_year as county_population_year` to mart_monthly_obligations, and add it to the
    schema.yml contract (data_type integer).
