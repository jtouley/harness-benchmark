## Gaps

- G-1 (blocking). No dedupe key and no resume position are named for stream events. The spec requires exact resume with no double count and no loss, and says the replay server disconnects. The candidate key is the recentchange `meta.id`. The resume position (SSE event id or Last-Event-ID, or a stored offset) and where it is persisted are not stated.
- G-2 (blocking). The lateness watermark is defined as the highest event time among earlier arrivals. The spec does not say whether that maximum persists across `make stream` runs and reconnects, or whether late events raise it. Check 7 and the on-time split in check 6 depend on this.
- G-3 (blocking). Check 3 counts "awards", but the fact grain is one transaction. The spec does not name the award key (for example `generated_unique_award_id`). It also does not say whether net obligation is summed per award over FY2024 transactions before the sign test.
- G-4 (blocking). The spec does not say whether place means place of performance or recipient location. It does not say how rows without a state or county are handled. Check 4 (county totals equal state totals, state totals equal the source total) fails or silently drops rows unless an unplaced rule exists.
- G-5 (blocking). Publication scope is unclear. The spec says downstream reads only `out/marts/`. It does not say whether the star-schema fact and dimension tables are published there. `oracle_map.yml` allows a "table or SQL view", which may point outside `out/marts/`.
- G-6 (non-blocking). Mart column names and types are not listed. The dbt contracts and `oracle_map.yml` cannot be written from the spec alone.
- G-7 (non-blocking). The source amount type and the money precision are not stated. "Summed exactly" needs a fixed DECIMAL precision.
- G-8 (non-blocking). Net bytes with a missing `length.old` or `length.new` is not defined. It is not stated whether such an event counts as an edit with 0 bytes.
- G-9 (non-blocking). The bot split uses the recentchange `bot` flag. The rule for a missing flag is not stated.
- G-10 (non-blocking). The wiki key for check 6 is not named. `en.wikipedia.org` must map to the stream `wiki` value (`enwiki`) through the sitematrix.
- G-11 (non-blocking). "The replayed hour" for check 5 has no start or end. It is not stated whether the hour is taken by event time or arrival time.
- G-12 (non-blocking). The population fallback says "latest earlier estimate". The join key (state and county FIPS) and the role of the 2021 file are not stated. `co-est2024-alldata.csv` has `POPESTIMATE2024` for all 3144 county rows, so the fallback applies only to keys absent from that file. The 2020 base (`ESTIMATESBASE2020`) must not be read as the population.
- G-13 (non-blocking). The write disposition for each dlt source is not stated. dlt appends by default. "Running twice must not change any output" needs replace or merge per source.
- G-14 (non-blocking). Check 2 has no rule for ties or very small populations.
- G-15 (non-blocking). The stack paragraph has no heading. Output 3 refers to "the stack section" without a name. Minor.
