# Pilot: Cadence on Haiku 5.5 vs an Opus 5.5 one-shot (T05 budgets, n = 1)

**Date:** 2026-10-13. **Stage:** 1 of [next steps](../next-steps.md) (the pilot decides only which arms go on). **Data:** [`2026-10-13-pilot/`](2026-10-13-pilot/).

## Question

Can Cadence on a cheap model (Haiku 5.5: 40× cheaper per token than Opus 5.5 for prompts up to 100 K tokens, 8× above that) deliver the T05 budgets feature, the only task where every iteration-4 one-shot shipped a crash? Two Cadence variants were run against an Opus 5.5 one-shot on the same prompt.

## Arms

| Arm | Orchestrator | Peers | Harness |
|---|---|---|---|
| `opus_oneshot` | `claude-opus-5-5` | none | none |
| `cadence_haiku` | `claude-haiku-5-5` | every peer on Haiku 5.5 (`peer_models: {"default": "haiku"}`) | Cadence at `3d9fc77` (cadence#62, the `peer_models` setting), as the operator noted it (see Setup) |
| `cadence_haiku_opus` | `claude-haiku-5-5` | Haiku 5.5, with P3, P6, P7, R1 and R2 on Opus 5.5 | same |

## Setup

- **Clean room.** Each run had its own empty `HOME`, with an API key and no user-level skill, rule, command, memory or settings. Cadence was loaded for that session only with `claude --plugin-dir`, so only its own commands and skills existed (namespaced `cadence:`). [`run_arm.sh`](2026-10-13-pilot/run_arm.sh) builds each run: `run_arm.sh ARM WORKSPACE` from this repository; it builds the workspace with the iteration-4 `make_workspace.sh` if needed.
- **Host.** Claude Code 2.1.287, headless (`claude -p`), permission mode `auto`. The `haiku` alias was pinned to `claude-haiku-5-5` with `ANTHROPIC_DEFAULT_HAIKU_MODEL`, so the `peer_models` alias resolves to Haiku 5.5. The Cadence commit and the host version come from the operator's notes: `run_arm.sh` did not record them then. It now writes both to `provenance.json` for each run. Claude Code prints an "unrecognized model" warning for that id but runs and bills it as `claude-haiku-5-5`.
- **No time cap.** No run was stopped. Each Cadence run ended on its own hard stop.
- **Grading.** [`grade_arm.sh`](2026-10-13-pilot/grade_arm.sh): the iteration-4 `grade.py` (hidden tests, procedure checks), the [quality model](../quality-model.md) tools, the clean-room check, and cost from token counts at [`pricing.json`](../../pricing.json) list prices. Claude Code does not know the Haiku 5.5 price, so its own dollar figure for those runs is wrong ($39.28 and $13.65 reported).

### Why the Cadence runs stopped

**`cadence_haiku`** went through A1 to P5 and P7 to P9. The adversarial review (P6) asked for changes four times. After each plan update it found new edge cases (amount digit limits, a negative amount read as a flag). Haiku then recorded a `retries` hard stop before E1. It passed P9: the stop came from P6, not from the delegation procedure. Its own summary also reports two provenance faults: the first adversarial run had no valid provenance record and was rerun, and a plan-update peer wrote the plan-review files for cycles 4 and 5. It named those verdicts invalid itself.

**`cadence_haiku_opus`** stopped at P9. Its reviews converged: P3 reached READY TO EXECUTE in cycle 4, and P6 passed in round 2 (from its own summary; the review files are not committed). It sent the peers full briefings, not the lean slash command. It did not record the delegations with `subagent_provenance.py begin`, and it wrote the peer outputs to the wrong folders. P9 then failed on the missing lean records, as it must. The all-Haiku arm recorded its delegations by hand and passed P9, so the procedure was the same in both arms. The Haiku orchestrator's compliance was not, in one run each. Claude Code does not write these records for the orchestrator (defect 2 below).

Both arms marked A4 (ticket gate) `TICKET_SKIPPED`: the environment has no tracker, and the gate has no mode for that.

### Clean room

`opus_oneshot` is `clean`. The two Cadence arms are `contaminated` by the rule, and on review that verdict is a false positive. Each contact is an unresolved shell path to the arm's own Cadence: `$HOME/.cursor/skills/cadence` and `${CADENCE_HOME:-...}` in `cadence_haiku`, `$C/skills/plan-review/SKILL.md` in `cadence_haiku_opus`. `$HOME` was the empty clean home, and no user-level file existed to read. `run_arm.sh` set `CADENCE_HOME` to the arm's own Cadence, so `${CADENCE_HOME:-...}` resolved there. No listed skill or skill call came from outside the arm. The checker cannot resolve shell variables, so these stay in `clean_room.json` as found, with this note as the adjudication.

## What the pilot says

- **The pilot rule:** drop an arm that cannot follow the Cadence procedure at all. By that rule:
  - `cadence_haiku` followed the procedure: it passed P9 with 4 of 4 verdict files attested. It stopped at P6, where Haiku reviewers kept finding new edge cases and Cadence has no cycle limit (defect 1). **Kept.**
  - `cadence_haiku_opus` did not record its delegations, and P9 stopped it. Its Opus reviews converged. Claude Code leaves the record to the orchestrator (defect 2). **Kept, pending defect 2.**
  - Both arms run again after the four defects are fixed. With n = 1 per arm, the pilot does not show whether Haiku 5.5 can orchestrate Cadence reliably. It shows two failure modes, and both trace to Cadence defects.
- **Cost:** the Cadence arms spent 3× and 8× the dollars of the Opus one-shot at the lower-bound price (up to 14× and 11× at the upper bound), and delivered nothing. The Opus one-shot delivered a correct, tool-clean change in under two minutes. T05 does not need a harness for Opus.
- **This is n = 1.** It does not measure the variance. It shows failure modes clearly enough to fix before more runs.

## Cadence defects found

These go to Cadence, not to the benchmark:

1. **P6 has no cycle limit.** (jtouley/cadence#63) P3 stops after five cycles and carries its findings into the plan. P6 has no such rule, so a model that finds new edge cases each round never reaches E1.
2. **On Claude Code, the lean delegation record depends on the orchestrator.** (jtouley/cadence#64) `hooks/hooks.json` does not run `guard_lean_task_prompt.py`. The orchestrator must run `subagent_provenance.py begin` by hand, and a weak orchestrator forgets. A hook can write the record.
3. **A4 has no mode for "no tracker".** (jtouley/cadence#65) An eval sandbox, or a repo with no issues, cannot bind a ticket.
4. **A peer wrote another stage's verdict.** (jtouley/cadence#66) The attestation records the writer. The plan-review gate must reject a verdict whose writer was not a plan-review peer.
